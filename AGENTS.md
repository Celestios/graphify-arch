# AGENTS.md

## Project Overview

`graphify-arch` — Python plugin for the [graphify](https://github.com/Celestios/graphify) fork. Adds architecture enforcement to code analysis: indexes code into a queryable graph, applies user-defined rules from `config.json`, audits violations, and provides context for AI agents.

## Quick Commands

```bash
# Activate venv (Python 3.13)
.venv\Scripts\activate

# Run all tests
python -m pytest tests/ -v

# Run single test file
python -m pytest tests/test_db.py -v

# Run single test
python -m pytest tests/test_db.py::TestDatabase::test_database_creation -v
```

No mypy, ruff, or other lint/typecheck tooling is configured. Tests use `unittest` framework discovered by pytest. Tests add `src/` to `sys.path` manually (no conftest.py).

## Architecture

### Source Structure

```
src/
├── plugin.py          # ArchPlugin — entry point for graphify plugin hooks
├── plugins.py         # Plugin discovery (importlib entry_points) + hook runner
├── main.py            # Standalone CLI dispatcher (separate from plugin CLI)
├── cli.py             # Argparse definitions for standalone commands
├── db.py              # SQLite Database, GraphBuilder, VectorSearchEngine, GraphTraverser
├── schema.py          # OntologyConfig, CodeNode, SemanticFacets, relation types
├── project.py         # ConfigLoader (walks up dirs for config), Workspace.discover()
├── propagator.py      # Metadata propagation through call graph
├── auditor.py         # Architecture rule auditing
├── embedder.py        # ONNX all-MiniLM-L6-v2 (384-dim) for semantic search
├── compiler.py        # Subgraph context compilation
└── references/        # arch-*.md documentation files (copied to skill dirs at install)
```

### Two CLI Entry Points

1. **Plugin CLI** (`graphify arch <cmd>`): Routes through `plugin.py:handle_cli()`. Available: `audit`, `analyze`, `set-status`, `update-component`, `discover-ontology`, `query-file`, `compile-context`, `semantic-search`, `install`, `setup-embeddings`.
2. **Standalone CLI** (`python -m src.main <cmd>`): Defined in `cli.py`. Commands: `discover-ontology`, `reindex`, `get-dirty-nodes`, `compile-context`, `audit`, `query-file`, `update-nodes`, `semantic-search`.

### Key Runtime Files (all gitignored under `graphify-out/`)

- `graphify-out/arch/config.json` — user-defined ontology rules (created by AI agent)
- `graphify-out/arch/graph.db` — SQLite database (nodes, edges, components, component_violations)
- `graphify-out/graph.json` — generated by graphify (input to this plugin)

### Data Flow

1. `graphify .` scans codebase → `graphify-out/graph.json`
2. Plugin `on_post_build` loads graph, syncs to SQLite, applies ontology rules, propagates metadata
3. Plugin `on_post_analyze` audits against dependency constraints, updates violations in DB
4. `graphify arch audit` queries DB for violation status per file

## Plugin System

Plugins implement `PluginHookInterface` (`src/plugins.py`). Discovered via `importlib.metadata.entry_points` under groups `graphify.plugins` and `graphify_arch.plugins`.

Entry point in `pyproject.toml`:
```toml
[project.entry-points."graphify.plugins"]
arch = "plugin:ArchPlugin"
```

Hooks execute in order: `on_post_extract` → `on_post_build` → `on_post_analyze` → `on_export` → `on_report`.

`run_hook()` chains the first argument as accumulator through all plugins.

## Gotchas

- **`root` parameter is str, not Path**: graphify passes `root` as a `str` to plugin hooks. All plugin code MUST do `root = Path(root)` before using `/` operator. Defensive conversion is in place in every hook method.
- **Config discovery walks up directories**: `ConfigLoader.find_config()` starts at cwd and walks up parent directories looking for `graphify-out/arch/config.json`. If not found, defaults to `<start>/graphify-out/arch/config.json`.
- **Database uses WAL journal mode**: `PRAGMA journal_mode=WAL` for concurrent reads. Database is file-backed at `graphify-out/arch/graph.db` (not in-memory).
- **Semantic search requires model download**: Run `graphify arch setup-embeddings` first. Downloads ONNX all-MiniLM-L6-v2 to `~/.arch/models/`.
- **Manual status overrides take precedence**: `manual_status` in DB overrides automated audit results in `update_violations_and_statuses()`.
- **`reset_on_change` flag**: Controls whether manual fields reset to default when file's AST hash changes.
- **Undirected graph edge direction bug (CRITICAL)**: NetworkX `G.edges` iterates undirected edges with node IDs alphabetically sorted. Auditor only checks `u → v` direction. Forbidden direction can be missed depending on alphabetical node ordering. User rejected "check both directions" fix. **Correct fix requires storing edge direction metadata from the AST extractor.** See MEMORY.md for details.
- **`SemanticFacets` is dynamic**: Uses `__getattr__` returning `"Unknown"` for missing keys. The `@dataclass` decorator is misleading — actual storage is a `fields` dict.
- **Plugin activation must not block CLI**: `should_activate()` always returns `True` so `handle_cli()` is reachable. Config checks are deferred to `handle_cli()` and hooks.
- **Config guard fires multiple times**: Running `graphify .` without config.json outputs the "not found" warning multiple times before extraction. Cosmetic, not blocking.
- **`graphify-out/` is gitignored**: All runtime output lives in gitignored directory. Never commit config.json, graph.db, or graph.json.
- **Python ≥3.10 required**: Declared in `pyproject.toml`. Dev machine uses Python 3.13.

## Tool Gotchas

- **Actor tool requires `operation` object**: Always pass a single `operation` JSON object with `action` as discriminator. All params (prompt, description, subagent_type, context) go inside `operation`, NOT as top-level params. Wrong: `actor({prompt: "...", subagent_type: "explore"})`. Correct: `actor({"operation": {"action": "run", "subagent_type": "explore", "description": "...", "prompt": "..."}})`
